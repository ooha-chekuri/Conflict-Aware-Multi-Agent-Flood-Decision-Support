# Research Guide Alignment Audit

**Project:** Conflict-Aware Multi-Agent Flood Decision Support System
**Status:** Audit complete; documentation only. No application code, raw inputs, labels, thresholds, or evaluation outputs were changed for this audit.
**Specification:** *Conflict-Aware Multi-Agent Flood Decision Support Beginner’s Project Guide* (27 pages, updated 30 October 2026), read together with the explicit accompanying user request.

## Executive finding

The existing project is a useful deterministic-first evidence review prototype, but it is **not yet aligned with the approved mini-project research design**. The three named agent classes exist, and the system has provenance fields, temporal safeguards, configurable source priors, deterministic conflict checks, abstention, a Streamlit UI, and versioned synthetic evidence. However, Incident Verification does not use the configured hosted LLM to extract claims from source text; all agents receive already-structured `Evidence`. The common claim contract is incomplete, guideline claims do not enter conflict detection, evidence weights do not use the specified weighted-sum formula, the planner lacks Monitor/Advisory/Prepare/Evacuate levels, and active v2/v3 evaluation does not run the specified B1/B2 baselines or ECE+Brier metrics.

The user explicitly requested the audit and deliverables first, then approval before implementation. This report and its companion architecture and plan are the only requested changes. **No application implementation has started.**

## How the specification was interpreted

The guide's `[Decided]`, `[Suggested]`, and `[Later]` labels remain meaningful. The accompanying user request separately makes some implementation choices explicit (notably agent responsibilities, one configured hosted LLM, common claim fields, and four action levels). Those are treated as project requirements even where the guide labels an implementation allocation `[Suggested]`.

| Tag | Guide items relevant to this audit |
|---|---|
| **[Decided] core** | General flood-only scope and human final authority (pp. 1–4); three specialists, ordinary components, no agent chat and shared claims (pp. 7–9); deterministic conflict/scoring path and four conflict families/formula (p. 10); abstention (pp. 6, 11); Godavari case for evaluation only (pp. 12, 15); six scenario types (p. 14); practice/final-test separation (p. 20); B1 Single AI, B2 three-agent majority, and four metric groups (p. 21). |
| **[Suggested] planning choices** | Which agent uses the LLM (p. 8); 15–25 extracted guideline rules (p. 16); approximately 30 scenarios, 10 practice/20 final test, 10–15 evidence items (p. 16; confirm against slides); Pydantic, plain Python orchestration, SQLite/JSON, Streamlit (pp. 17–18); examples for computing factors (p. 11). The user's request explicitly adopts the role allocation and API-driven LLM as implementation requirements. |
| **[Later] major-project scope** | Fourth roads/infrastructure agent, live feeds, semantic LLM conflict detection, additional baselines/metrics, additional floods/regions, learned/adaptive weights, dynamic agents, memory/replanning, human studies and deployment (pp. 8, 10, 22, 24–26). Keep these out of mini-project alignment work. |

The guide says final coefficient/threshold values are not decided and should be tuned only on practice scenarios (pp. 11–12). This audit does not select or tune them.

## Preservation and reusable work

The separate v2/v3 synthetic inputs, labels, metrics and prior validation reports remain available and were not regenerated or retuned. Reusable components include Pydantic validation, API/UI, temporal availability safeguards in the v2 path, numerical comparability and geographic safeguards, source-prior documentation, page-cited NDMA retrieval, v3 source-independence validation, and regression tests.

The previously completed validation recorded 40 automated tests passing. Tests were not rerun for this documentation-only audit.

## Required corrections before guide-aligned experiments

1. Canonical claims and complete three-agent routing.
2. Hosted LLM incident extraction, bounded Weather explanation, and versioned model traces.
3. Deterministic guideline rule matching and rule citations.
4. Four conflict families, specified weighted-sum evidence formula, and four action levels with abstention.
5. Real B1 and B2 baselines on identical inputs.
6. Separate practice/final data, second-reader gold labels, locked parameters and guide metrics.
7. Reviewed rainfall cleaning and a safe historical data path that cannot restore the old availability assumption.

The architecture and phase-by-phase plan are in the companion documents. The first implementation task proposed for approval is **the canonical claim contract with backward-compatible adapters and an integration test proving claims from all three agents reach deterministic conflict detection**. No implementation has begun.
